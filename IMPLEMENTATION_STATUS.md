# Implementation status

Living progress tracker for `ttu-platform`'s backend build-out. Updated as work lands — read
this first to see what exists, what's next, and what's deliberately blocked before touching
`apps/api`. See [docs/setup.md](docs/setup.md) for how to run/verify any of the pieces below,
and [AGENTS.md](AGENTS.md) for the wiring-order rule this list follows.

## Blocked — do not build speculatively

| #   | Area                                                                             | Blocked on                                                                                         | Why it can't be faked                                                                                                                                                                                                                                                                                                                                                                                                       |
| --- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| —   | CMS Page Builder (`pages`, `page_sections`, publish/revision/rollback for pages) | A Component Registry (`packages/cms-registry`) and a real ~15-20-component set (design docs 02-03) | Publishing a page requires validating `component_key`/`component_version`/`config`/`style` against a registry that is code, not data. That registry doesn't exist in this repo yet — building it means inventing real product/design decisions (which components exist, their exact field schemas, style tokens), not implementing a spec. `pages`/`page_sections` tables exist in the schema; no endpoints exist for them. |

## Not started (not yet scoped/requested)

- Navigation domain (`menus`, `menu_items`) — schema exists, no endpoints. Full usefulness needs `pages` to exist for internal links, which is blocked above; external/custom-path links could go first if requested.
- Redirects domain as a standalone admin surface — `redirects` rows are currently only written automatically by Content publish (path-change auto-redirect); no manual CRUD for admins yet.
- Site settings domain (`site_settings`) — schema exists, no endpoints, no Settings Registry (design doc 06 §12 requires one).
- Audit log read endpoint (`audit_logs`) — rows are written by publish/restore already; no `GET` surface yet.
- `apps/web` — still the Next.js scaffold default homepage; nothing reads the Public API yet.
- WordPress migration tooling (design doc 09).
